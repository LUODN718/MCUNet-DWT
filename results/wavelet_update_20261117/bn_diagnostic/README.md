# 固定第18轮与第20轮的TRAIN侧BN重估诊断

这是独立的训练后诊断，不改变原实验记录，也不将重估后指标冒充原始训练成绩。
输入为已封存的两份本地完整checkpoint：第18轮最低LL-pad开发CE模型和固定第20轮模型。
诊断前复制到`inputs/`，按内容SHA256校验，原始权重不覆盖。

先复测两份权重的原图/LL1补零完整20k开发指标，并与原history逐项核对。
然后每份权重分别建立RGB与LL1-pad两个BN统计版本：

- 从冻结128k训练名单每类取前16张，共16000张，seed2026置乱，先封存样本再看开发结果。
- 使用原训练RRC160和翻转（epoch0），RGB或LL1-pad各自独立校准；标签不参与计算。
- 所有参数禁止梯度；整个模型eval，只将BN模块置train，避免启用dropout。
- 重置BN运行均值/方差/计数，momentum=None，对500个batch32作累积平均。
- 每份权重、每个视图都从该原始checkpoint单独开始；仅三个BN运行buffer允许变化。
- BN校准完成后，模型eval，按对应视图评估完整20000张开发集。
- 不用开发集估计BN，不用官方val，不选择校准样本数或根据开发成绩调整校准配方。

500批统计由上游层在校准期使用批内BN的前向得到，是标准批次BN重估诊断，
不声称等于全数据精确逐层总体方差，也不能据此推断所有性能差距均由BN导致。
即使本诊断有改善，后续正式方法也需要预先冻结独立的训练/推理统计协议。

校准状态每50批保存，可从固定游标继续；开发累计指标每50批保存，完整20000才发布结果。
逐例JPEG字节和解码RGB检查沿用冻结读取器，无缓冲读原始tar，不解包图片。
`results.csv/json`给出原始/校准后对照，`outputs/`保留BN buffer、哈希和完整评估计数。
诊断检查除BN运行buffer外的所有模型张量SHA256完全不变，不运行优化器、不更新卷积/分类头。
`status.json`为实时进度，日志在`logs/`。

本诊断与当前旧原图控制训练使用独立进程、独立模型状态；旧队列后续LL-only先暂缓，
为诊断后的复现适配提供顺序执行位置，不更改旧训练合同。
