# 低分辨率与轻量增强：RGB80 / Haar LL80 子集实验

本轮目标是实际减少 MCUNet 主干的计算，而不是把 LL 放大回160分析细节。
使用同一160×160几何视图，分别做普通bicubic抗混叠缩小或一级Haar低频提取，
直接以3×80×80送入原MCUNet-in2。原始3×3 stride2首层和全部骨干通道保留，
首层输出40×40，后续特征图也缩小；没有插值放大、剪枝、蒸馏或新首层。

## 对照设计与运行顺序

|组别|输入|额外增强|处理|
|---|---|---|---|
|LL80-light|同一RGB160视图→Haar LL80，幅值校正|轻量颜色扰动、小面积遮挡|首先训练|
|RGB80-light|同一RGB160视图→bicubic抗混叠80|同上、同一逐图种子|随后训练|
|RGB80-plain|同一RGB160视图→bicubic抗混叠80|无|随后训练|
|LL80-plain|Haar LL80|无|复用20261101已完成的同本地内容、同原始配方记录|
|RGB160-plain|RGB160|无|复用历史基线，仅作计算量与原配方参照|

LL80-plain已有开发Top-1 48.305%，RGB160-plain为65.630%。历史指标不能替代
本轮增强后的结果，不能把相对RGB160的差异全部归因于DWT。RGB160没有本轮的额外
增强；本轮的增强因果对照仅限80分辨率的RGB/LL组。先检验两种低分辨率输入的差异，
以及在相同低分辨率输入上增强是否有效。新结果全部按完整20k开发集最低CE选轮。

## 输入与增强

所有组仍从原始ImageNet TRAIN图片取固定规则的RandomResizedCrop160，
scale[0.08,1]、ratio[0.75,4/3]、bicubic+antialias，水平翻转0.5。
新增增强只在TRAIN，位于上述几何处理后、RGB/LL降采样前：

- 以0.8概率使用ColorJitter：亮度/对比度/饱和度0.15，色调0.02。
- 以0.1概率做RandomErasing：面积2%–8%，宽高比0.3–3.3，填RGB0.5。
- 额外增强由seed2026、轮次和样本路径独立生成；RGB和LL使用相同增强视图，
  不消耗全局训练RNG，恢复训练不改变某个样本的增强。
- 不使用mixup/cutmix、标签平滑、训练副本扩充或增加更新次数。

开发集保持短边182、中心裁剪160，再做该组的确定性降采样；没有颜色扰动或遮挡。
Haar LL每级直流增益2，本轮LL除以2后执行2*x-1；该归一化与历史直接LL80完全一致。
RGB80在浮点bicubic后clamp[0,1]，再做2*x-1。
Haar低频等价2×2均值池化；该对照不能单独证明小波优于所有普通降采样器。

## 数据、训练与选轮

固定128,000张TRAIN＋20,000张开发集，1000类，不运行全量训练，不重抽样。
本地图片字节/RGB封存与前面自己的RGB/LL实验一致，但与队友封存不完全一致；
新增增强也改变了原冻结配方，本轮明确为独立实验，不能称为原队友协议结果。

同一官方MCUNet-in2预训练，保留1000类头；全部参数和BN训练，BN momentum0.1、eps1e-5。
seed2026，FP32，AMP/TF32关闭；batch=effective=BN=32，无梯度累积。
普通CE；SGD momentum0.9、WD4e-5，含BN/bias；全部参数峰值LR0.001。
前2轮warmup包括在最多20轮cosine内，4000更新/轮；早停沿用至少6轮、
连续4轮改善不足0.001且最近4轮斜率绝对值≤0.001、极差≤0.005的联合规则。
按完整20k开发CE最低选最佳，不用官方val/V2调参。本轮未安排官方测试集评估。

## 计算量与运行可靠性

RGB160历史结构为67,287,200 Conv/Linear MAC/张；本轮RGB80和LL80均为
18,021,824 MAC/张，约减少73.22%，参数仍为729,392。实际数值由CPU真实
forward形状审计，不包含DWT、resize、归一化、BN、激活、解码和搬运。
降低MAC不等于相同比例的时间收益，另外记录GPU forward实测，不宣称MCU速度。
增强只在训练期，不增加上述推理CNN MAC，也不保证能恢复精度。

使用已有tar无缓冲按图读取，不解包原图，不设置系统内存阈值暂停或报警。
workers0/prefetch1，单实验串行；真实CUDA OOM或文件占用最多从完整断点重试3次，
其他错误停止并保留现场。每100步或60秒保存模型、BN、优化器、调度器、RNG、
样本游标和训练统计。恢复时逐项校验源码、数据和训练合同，不能偷改配方继续。
队列防止电脑因空闲自动睡眠，退出时释放该线程请求，不修改系统全局电源设置。

所有新源码、索引副本、日志、权重和缓存均在此fyp目录。
`queue_status.json`查看当前组，`runs/<组别>/progress.json`查看实际更新数；
`results.csv`只收已完成组的最低CE选轮结果，历史复用行单独标记。
`preflight.json`是开跑前检查，不是正式训练成绩。双击`resume_queue.cmd`可恢复队列；
已有队列运行时不要重复启动，操作系统锁会阻止重复运行。
