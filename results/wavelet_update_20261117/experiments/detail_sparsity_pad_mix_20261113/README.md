# 原图与LL1补零混合训练 MCUNet160适配

2026-11-13用户明确要求：当前RGB80-light跑完后取消RGB80-plain，开始今天讨论的
补零混合训练。`detail_sparsity_lowres_aug_20261112/PAUSE_QUEUE`已建立，
只阻止旧队列下一组，不中断当前训练。新队列检查RGB80-light完成20轮、
其训练锁和旧队列锁均释放之后才启动，不同时跑两个正式训练。

## 输入与方法假设

参考《通道观察》写的是224图像→LL112/56/28→补0至224，没有规定位置、
幅值、归一化顺序和混合比例。本次明确为160适配，不称精确复现224实验。
采用今天实验计划列出的假设：

- 原始ImageNet解码→固定几何RRC160/翻转；或开发短边182、中心160。
- 一级正交Haar，LL80除以2校正直流增益，固定左上角，右/下侧补0到160。
- 补0在[0,1]像素/校正系数域进行，再对整幅画布做2*x-1，填充区网络输入为-1。
- 不放大、不逆变换、不随机移动、不额外加颜色/遮挡增强；第一级先不加入LL2/LL3。
- 原始MCUNet-in2、原dense3×3 stride2、全骨干、1000类头；全部参数与同一套BN更新。
- 所有组729392参数、67.2872M CNN MAC/张，补零本身没有带来稠密CNN加速。

## 串行顺序

|组别|训练视图|每轮预算|目的|
|---|---|---|---|
|P2 原图＋LL1补零|RGB160/LL1-pad160各50%|2000 RGB batch＋2000 LL batch|首先直接检验用户要求的混合训练|
|P0 原图单独|只用RGB160|4000 batch|同数据/预算/双视图评估的匹配对照|
|P1 LL1补零单独|只用LL1-pad160|4000 batch|区分混合训练和单独LL训练的作用|

各组均从同一官方预训练开始，独立优化器和调度器，不沿用旧低分辨率权重。
P2每个batch32内部同视图，按seed2026和轮次确定性打乱4000个batch的视图选择，
每轮恰好2000+2000；样本顺序仍沿用冻结置乱，每张训练图每轮只出现一次。
不是增加一倍训练数据，不是图像相加或拼通道，不使用分支BN、蒸馏或自适应路由。
P0/P1是今天已规划的同预算对照，取消的RGB80-plain不会恢复。

## 数据 训练与评估

固定128000 TRAIN＋20000开发，1000类，不全量、不重新抽样。
同本地原图字节/RGB封存，manifest SHA256为
`0c68acdffbec6ec80835561962d94689eff4fdde5a3428858b5a117dd10653a7`；
与队友图片内容封存不同，不声称严格匹配队友。逐样本检查字节和解码RGB。

seed2026；batch=effective=BN=32，无累积；FP32，AMP/TF32关闭；
普通CE、无label smoothing；SGD momentum0.9、WD4e-5，含BN/bias；
所有参数峰值LR0.001；2轮warmup包括在最多20轮cosine内，每轮4000步。
BN momentum0.1、eps1e-5，共享运行统计，不额外做BN校准。
RRC160 scale[0.08,1] ratio[0.75,4/3]，bicubic+antialias，翻转0.5。

每轮同一完整20k开发图，分别按LL1补零160和原图160做eval；每图两次前向，
不反向、BN不更新。所有组统一按**LL1补零完整开发CE最低**选模型，
历史字段`dev_ce/top1/top5`是LL1补零主指标；`rgb_dev_*`是同一轮原图指标。
不能把最高原图Top-1的轮次与最低LL开发CE的轮次拼成一个模型结果。
主指标联合早停：至少6轮，连续4轮相对参考改善不超过0.001，最近4轮
斜率绝对值≤0.001/轮、极差≤0.005。预算最多20轮。
不使用官方val/V2调参，不安排官方测试。新结果出现在`complete.json`后才算完成。

## 准入 恢复与进度

`preflight.json`记录输入数值/幅值/补零、精确混合数量、真实tar几何和恢复检查、
共享BN、真实前向MAC、两种训练视图的失败回滚与精确重放；这些是CPU检查，非正式训练成绩。
`visualization/padding_vs_upsampling.png`展示真实开发图，系数块保持小尺寸，没有插值铺满画布。

无系统内存阈值看门狗、无报警；workers0/prefetch1，无缓冲按图读tar，不解包图片。
完整状态每100步或60秒保存，包含BN、优化器、调度器、RNG、样本游标和两类视图计数。
视图路由由已提交步数计算，断点续训不改变下一批类型。
真实CUDA OOM/PermissionError最多按完整断点恢复3次；其他异常记录后停止。
只防止因空闲自动休眠，不更改系统全局电源设置；用户主动休眠/关机仍会停止训练。

双击本目录`resume_queue.cmd`恢复等待或训练；已有队列运行时不要重复启动。
`queue_status.json`给出当前组；`runs/<组别>/progress.json`给出持久化步数和本轮视图计数；
`history.csv`记录完整双视图指标。所有源码、权重、索引副本、缓存及日志均在fyp内。
如需取消后续组，可建立本目录`PAUSE_QUEUE`，它不会中断当前训练。
